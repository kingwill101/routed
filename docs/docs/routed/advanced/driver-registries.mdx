# Driver Registries

Driver registries are adapter-level extension points. They are not a second
application configuration system: construct the typed provider configuration
first, then register the driver or backend during application composition.

## Storage

`routed_storage` supports local disks through `StorageConfig` and re-exports
`server_storage`'s `S3StorageDisk` and `SftpStorageDisk`. Register remote or
custom disks on an application-owned `StorageManager` and pass that manager
explicitly:

```dart
import 'dart:io';

import 'package:routed/routed.dart';

final environment = Platform.environment;
final assets = S3StorageDisk(
  endpoint: 'https://objects.example.test',
  accessKey: environment['S3_ACCESS_KEY']!,
  secretKey: environment['S3_SECRET_KEY']!,
  bucket: 'assets',
);

final manager = StorageManager()
  ..registerDisk('assets', assets)
  ..setDefault('assets');

final engine = await Engine.create(
  providers: [
    ...Engine.defaultProviders,
    RoutedStorageProvider(manager: manager),
  ],
);

final storage = manager.storage('assets');
await storage.put('images/logo.png', logoBytes);
```

For host-native object stores without a `package:file` implementation, such
as a Cloudflare Worker R2 binding, use `registerFilesystem()`. These backends
support `ctx.storage()` and asynchronous storage handlers. They do not expose
`manager.disk()` or local path resolution. Private backends such as R2 should
use `engine.signedStorage()`.

Use `RoutedStaticProvider` with a typed `StaticConfig` when the disk should
serve public files.

## Cache

Cache runtime ownership belongs to `routed_cache` and `server_cache`:

```dart
final manager = DataCacheManager();
manager.registerStoreFactory(
  'custom',
  CustomStoreFactory(),
  const CustomStoreConfiguration(/* typed options */),
);

final engine = await Engine.create(
  providers: [
    ...Engine.defaultProviders,
    RoutedCacheProvider(CacheConfig(store: manager.store('custom').getStore())),
  ],
  options: [withCacheManager(manager)],
);
```

`DataCacheManager` accepts concrete stores, while its factory helper accepts
typed `StoreConfiguration` values. The manager and `withCacheManager` option
are exported by
`package:routed_cache/routed_cache.dart`; they are deliberately absent from
`routed_core`.

## Logging

`routed_logging` exposes `LogDriverRegistry`. Register a contextual driver
before `LoggingServiceProvider` boots:

```dart
final registry = LogDriverRegistry();
registry.register('webhook', (context) {
  final url = Uri.parse(context.options['url'] as String);
  return contextual.WebhookLogDriver.fromOptions(
    contextual.WebhookOptions(url: url),
  );
});

final engine = Engine(
  providers: [
    ...Engine.defaultProviders,
    LoggingServiceProvider(
      LoggingConfig(
        channels: {
          'webhook': LoggingChannelConfig(
            name: 'webhook',
            driver: 'webhook',
            options: {'url': 'https://logs.example.test/ingest'},
          ),
        },
      ),
    ),
  ],
);
engine.container.instance<LogDriverRegistry>(registry);
await engine.initialize();
```

`LogDriverBuilderContext` provides the typed `LoggingConfig`, channel name,
options, and container. Driver validators and documentation callbacks operate
on the registry entry; invalid typed provider configuration fails before boot.

## Authentication providers

OAuth provider registries are populated with typed provider factories, but a
Routed engine receives the resulting provider objects through
`AuthOptions.providers`:

```dart
final authOptions = AuthOptions<EngineContext>(
  providers: [
    googleProvider(
      GoogleProviderOptions(
        clientId: clientId,
        clientSecret: clientSecret,
        redirectUri: redirectUri,
      ),
    ),
  ],
);
```

This keeps provider secrets and redirect choices at the application boundary.

## Extension rules

- Register custom drivers before the owning provider initializes.
- Use `overrideExisting` only when intentionally replacing a built-in driver.
- Keep driver-specific options close to the typed provider that owns them.
- Add integration tests for startup, failure, and cleanup paths.
- Do not expose driver credentials or filesystem paths in client error bodies.
