# Engine lifecycle

`Engine` owns the request lifecycle, container, routers, middleware, and server
transports. Providers are registered explicitly and booted once.

## Recommended composition

Use the batteries-included package when you want the official provider set, or
list only the providers your application needs:

```dart
import 'package:routed/routed.dart';

final engine = await Engine.create(
  providers: [
    CoreServiceProvider(
      EngineConfig(
        security: EngineSecurityFeatures(
          maxRequestSize: 10 * 1024 * 1024,
        ),
      ),
    ),
    RoutingServiceProvider(
      const RoutingConfig(handleMethodNotAllowed: true),
    ),
    UploadsServiceProvider(
      MultipartConfig(allowedExtensions: {'jpg', 'png'}),
    ),
  ],
);
```

`Engine.create` initializes the engine before returning it. For a bare engine,
use `Engine()` or `Engine.create(providers: const [])`; bare engines still have
the router and middleware pipeline but no typed provider configuration.

## Provider boot order

The lifecycle is:

1. Construct the engine and register providers.
2. Register provider services and collect typed configuration objects.
3. Validate every typed configuration and aggregate all failures.
4. Boot providers in dependency order.
5. Register routes and serve requests.

Configuration and runtime context are fixed once initialization starts. A
provider cannot be enabled from a string manifest, and configuration cannot be
reloaded while requests are active.

## Runtime context

Use `RuntimeContext` for environment values, secrets, and platform bindings:

```dart
final engine = await Engine.create(
  runtime: RuntimeContext(
    environment: RuntimeEnvironment({'APP_ENV': 'production'}),
    secrets: RuntimeSecrets({'SESSION_KEY': sessionKey}),
    bindings: {Object: platformBinding},
  ),
  providers: [
    CoreServiceProvider(),
    RoutingServiceProvider(),
  ],
);
```

Portable provider configuration should not contain `dart:io`, JavaScript
interop, or Cloudflare-specific objects. Those belong in runtime bindings and
are resolved by the platform adapter.

## Engine options

`EngineOpt` is reserved for wiring, not provider configuration:

```dart
final engine = Engine(
  providers: [CoreServiceProvider(), RoutingServiceProvider()],
  options: [
    withMiddleware([requestIdMiddleware()]),
    withService<AuditWriter>(AuditWriter()),
  ],
);
await engine.initialize();
```

Use the provider constructor for settings such as CORS, trusted proxies,
logging, storage, sessions, uploads, and views. Provider settings are assembled
once before startup and remain immutable for the engine lifetime.

## Serve and close

```dart
final engine = await Engine.create(
  providers: [CoreServiceProvider(), RoutingServiceProvider()],
);

engine.get('/health', (ctx) => ctx.json({'status': 'ok'}));
await engine.serve(host: '127.0.0.1', port: 8080);

await engine.close();
```

In tests, close every engine and client you create. `routed_testing` and
`server_testing` provide helpers that manage those lifetimes for you.
