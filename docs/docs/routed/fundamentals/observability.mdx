# Observability

`routed_observability` provides typed configuration for tracing, metrics,
health endpoints, and error observers. Register `ObservabilityServiceProvider`
with only the capabilities the application needs.

## Configure the provider

```dart
import 'package:routed/routed.dart';

final engine = await Engine.create(
  providers: [
    ...Engine.defaultProviders,
    ObservabilityServiceProvider(
      ObservabilityConfig(
        tracing: ObservabilityTracingConfig(
          enabled: true,
          exporter: 'otlp',
          serviceName: 'checkout-api',
          endpoint: Uri.parse('https://otel.example.com/v1/traces'),
          headers: {'authorization': 'Bearer $otelToken'},
        ),
        metrics: ObservabilityMetricsConfig(
          enabled: true,
          path: '/metrics',
        ),
        health: ObservabilityHealthConfig(
          enabled: true,
          readinessPath: '/readyz',
          livenessPath: '/livez',
        ),
      ),
    ),
  ],
);
```

Configuration is validated before provider boot. Supported tracing exporters
include `none`, `console`, and OTLP variants. Sentry is configured with
`ObservabilitySentryConfig` and requires a DSN when enabled.

## Metrics and health

When metrics are enabled, the provider exposes a Prometheus-style endpoint at
the configured path. The built-in metrics cover request count, duration, and
active requests. Pull `MetricsService` from the container to add application
metrics.

Health endpoints return readiness and liveness JSON responses. Register checks
through `HealthService`:

```dart
final health = await engine.container.make<HealthService>();
health.registerReadinessCheck('database', () async {
  final ok = await db.isHealthy();
  return ok
      ? HealthCheckResult.ok({'pong': true})
      : HealthCheckResult.failure({'error': 'timeout'});
});
```

Readiness failures return `503 Service Unavailable`; liveness is intended to
report whether the process itself can serve requests.

## Error observers and events

`ErrorObserverRegistry` forwards unhandled request failures to an error tracker.
Observers receive the request context, error, and stack trace. Keep observer
failures isolated from request handling and sanitize any external report.

The core `EventManager` is also available for application events and routing
events such as `RouteMatchedEvent` and `RoutingErrorEvent`.
