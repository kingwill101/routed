# Structured Logging

Routed provides a request-scoped logger backed by `contextual`. The logging
provider adds request metadata such as request ID, method, path, and status.
Prefer structured fields over interpolated strings and never log secrets or
full sensitive payloads.

## Log from a handler

```dart
engine.get('/status', (ctx) {
  ctx.logger.info('health check passed');
  return ctx.json({
    'status': 'ok',
    'request_id': ctx.loggerContext['request_id'],
  });
});
```

Use `LoggingContext.withValues` to add temporary request metadata:

```dart
await LoggingContext.withValues({
  'job_id': job.id,
  'user_id': ctx.get<int>('user_id'),
}, (logger) async {
  logger.info('job queued');
  await queueJob(job);
});
```

## Configure the provider

`LoggingServiceProvider` owns a typed `LoggingConfig`:

```dart
import 'package:routed/routed.dart';

final engine = await Engine.create(
  providers: [
    ...Engine.defaultProviders,
    LoggingServiceProvider(
      LoggingConfig(
        errorsOnly: false,
        includeStackTraces: false,
        extraFields: {
          'service': 'checkout-api',
          'deployment': 'production',
        },
        requestHeaders: ['X-Correlation-ID', 'X-Request-ID'],
      ),
    ),
  ],
);
```

The configuration also exposes typed channel definitions through
`LoggingChannelConfig`, plus `LoggingFormatConfig` for a custom formatter.
Built-in channels include `stdout`, `stderr`, `null`, `single`, `daily`, and
`stack`. Register custom drivers with `LogDriverRegistry` before the provider
boots.

## Custom logger output

For an application-wide sink, configure a factory at startup:

```dart
RoutedLogger.configureFactory((context) {
  final logger = contextual.Logger()
    ..withContext(context)
    ..setListener((entry) {
      sendToObservability(entry.record.toJson());
    });
  return logger;
});
```

Call `RoutedLogger.reset()` in test teardown when replacing the global factory.
Provider configuration is validated before boot and remains fixed for the
engine lifetime.

## Correlation and errors

Add a correlation ID with middleware and keep the browser response generic when
an exception occurs. The engine error hooks and `RoutingErrorEvent` let the
logging provider record the server-side error and stack trace without leaking
internal details to clients.
