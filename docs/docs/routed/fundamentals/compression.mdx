Routed includes an opt-in `routed.compression` provider. Call
`registerRoutedProviders()` before creating the engine, then enable gzip in
`compression.*` configuration. The provider compresses eligible buffered
responses and leaves streaming responses untouched.

The provider currently supports gzip. Brotli remains a host/proxy concern until
an encoder is added.

## Enablement and defaults

Configure it in `config/http.yaml`:

```yaml title="config/http.yaml"
compression:
  enabled: true
  min_length: 1024           # bytes before compression kicks in
  algorithms: [gzip]
  mime_allow:
    - text/*
    - application/json
    - application/javascript
  mime_deny:
    - image/*
    - audio/*
    - video/*
```

## Programmatic setup

```dart
import 'package:routed/routed.dart';

Future<void> main() async {
  registerRoutedProviders();
  final engine = await Engine.create(
    configItems: {
      'compression': {
        'enabled': true,
        'min_length': 1024,
        'algorithms': ['gzip'],
      },
    },
  );

  engine.get('/payload', (ctx) => ctx.json({'message': 'large response'}));
  await engine.serve(port: 8080);
}
```

## Runtime behavior

- Compression is negotiated through `Accept-Encoding: gzip` and responses add
  `Content-Encoding: gzip` plus `Vary: Accept-Encoding`.
- Responses smaller than `min_length`, denied MIME types, already encoded
  responses, `204`/`304` responses, and `HEAD` responses are not compressed.
- Streaming and SSE responses remain uncompressed so flush and heartbeat
  behavior is preserved.
- Configure Brotli or compression for other transports at the reverse proxy or
  host layer.
