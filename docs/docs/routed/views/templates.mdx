# Liquid Templates

Routed bundles a Liquid view engine. Configure it with
`ViewServiceProvider(RoutedViewConfig(...))` and render templates from a
handler.

## Configure the view provider

```dart
import 'package:routed/routed.dart';

final engine = await Engine.create(
  providers: [
    ...Engine.defaultProviders,
    RoutedStorageProvider(
      configuration: StorageConfig(
        defaultDisk: 'resources',
        disks: {
          'resources': const LocalStorageDiskConfig(root: 'resources'),
        },
      ),
    ),
    ViewServiceProvider(
      RoutedViewConfig(
        engine: 'liquid',
        disk: 'resources',
        directory: 'views',
        cache: true,
      ),
    ),
  ],
);
```

The provider resolves `directory` relative to the selected disk. Without a
disk, the directory is resolved through the engine’s file system. Configuration
is immutable after startup, so create a new engine when changing the view
root.

## Render a template

```dart
engine.get('/welcome', (ctx) async {
  return ctx.template(
    templateName: 'welcome.liquid',
    data: {
      'user': {'name': 'Taylor'},
      'features': ['sessions', 'cache', 'validation'],
    },
  );
});
```

Place the file at `resources/views/welcome.liquid`:

```liquid
<h1>Hello {{ user.name }}!</h1>
<ul>
  {% for feature in features %}
    <li>{{ feature }}</li>
  {% endfor %}
</ul>
```

Values are HTML-escaped by default. Use a raw filter only for content that has
already been trusted or sanitized.

## Inline fragments

Use `ctx.html` for a small template fragment and `ctx.string` for literal HTML
that should not be interpreted by the view engine:

```dart
return ctx.html('<p>{{ message }}</p>', data: {'message': 'Success!'});
```

## View extensions

`ViewExtensionRegistry` allows a provider to register engine-specific filters
or tags without coupling the route layer to Liquid:

```dart
import 'package:liquify/liquify.dart' as liquid;
import 'package:routed/routed.dart';

ViewExtensionRegistry.instance.registerFor('liquid', (target) {
  final environment = target as liquid.Environment;
  environment.registerLocalFilter('markdown', (value, args, named) {
    return renderMarkdown(value.toString());
  });
});
```

## Errors and custom engines

Missing templates and render failures raise the view package’s render
exceptions. Handle them at the route or engine error boundary and return a
generic client response; do not expose template paths in production.

Implement `ViewEngine` and register it with `ViewEngineManager` when Liquid is
not the right renderer. The provider currently validates the configured engine
and falls back only to the supported Liquid engine.
