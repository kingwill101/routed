# Rate limiting

`server_rate_limit` supplies the framework-agnostic policy runtime and
`routed_rate_limit` registers that runtime with an engine. Policies are built
in Dart and passed to `RateLimitService`; there is no YAML policy loader.

## Build a service

This example uses an in-memory cache repository. Use a shared repository (for
example, Redis) when limits must be consistent across multiple instances.

```dart
import 'package:routed/routed.dart';
import 'package:server_cache/server_cache.dart';
import 'package:server_rate_limit/server_rate_limit.dart';

final repository = RepositoryImpl(ArrayStore(), 'rate-limit', '');
final backend = CacheRateLimiterBackend(repository: repository);

final policies = compileRateLimitPolicies(
  specs: [
    RateLimitPolicySpec(
      name: 'api-ip',
      match: '/api/**',
      method: null,
      strategy: RateLimitStrategy.tokenBucket,
      capacity: 100,
      interval: const Duration(minutes: 1),
      window: const Duration(minutes: 1),
      period: const Duration(days: 1),
      burstMultiplier: 2,
      key: const RateLimitKeySpec.ip(),
    ),
  ],
  backend: backend,
  defaultFailover: RateLimitFailoverMode.allow,
);

final service = RateLimitService(policies);
final engine = await Engine.create(
  providers: [
    ...Engine.defaultProviders,
    RoutedRateLimitProvider(RateLimitConfig(service: service)),
  ],
);
```

`RateLimitPolicySpec` supports `tokenBucket`, `slidingWindow`, and `quota`
strategies. Use `RateLimitKeySpec.header('x-tenant-id')` for an authenticated
tenant key or implement `CustomResolver` for application-specific identity.

## Enforce a route

The adapter middleware makes the configured service available in the request
container. Enforcement remains explicit so applications can choose their
response shape and which routes are limited:

```dart
engine.get(
  '/api/items',
  (ctx) async {
    final outcome = await ctx.checkRateLimit(
      _Request.fromContext(ctx),
    );
    if (outcome != null && !outcome.allowed) {
      return ctx.abortWithStatus(
        429,
        'Retry in ${outcome.retryAfter.inSeconds}s',
      );
    }
    return ctx.json({'items': []});
  },
  middlewares: [rateLimitMiddleware(service)],
);
```

Implement `_Request.fromContext` as an adapter from your request context to
`RateLimitRequest`, including `method`, `path`, `clientIP`, `remoteAddr`, and
`header`. Do not use an untrusted forwarded IP unless the security provider is
configured with the correct trusted proxy networks.

## Failover and operations

`RateLimitFailoverMode.allow` fails open, `block` fails closed, and `local`
uses the backend’s per-process fallback. Choose the mode according to the
resource being protected. Attach `RateLimitEventCallbacks` to publish allowed,
blocked, and failover outcomes to your observability provider.
