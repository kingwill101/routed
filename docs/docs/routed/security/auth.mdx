# Authentication & Authorization

Routed authentication is composed from typed runtime options and explicit
middleware. `server_auth` provides the framework-agnostic auth models and
providers; `routed_auth` connects them to `EngineContext`.

## JWT bearer authentication

Use the direct middleware when an application only needs bearer verification:

```dart
import 'package:routed/routed.dart';

final jwt = jwtAuthentication(
  JwtOptions(
    issuer: 'https://issuer.example.com',
    audience: ['api'],
    requiredClaims: ['exp', 'scope'],
    jwksUri: Uri.parse(
      'https://issuer.example.com/.well-known/jwks.json',
    ),
    algorithms: ['RS256'],
  ),
);

engine.get(
  '/profile',
  (ctx) {
    final claims = ctx.request.getAttribute<Map<String, dynamic>>(
      jwtClaimsAttribute,
    );
    return ctx.json({'subject': claims?['sub'], 'scope': claims?['scope']});
  },
  middlewares: [jwt],
);
```

Verification failures return a generic `401 Unauthorized` response while the
server-side exception remains available to logging and error observers.

## OAuth token introspection

```dart
final introspection = oauth2Introspection(
  OAuthIntrospectionOptions(
    endpoint: Uri.parse('https://auth.example.com/oauth/introspect'),
    clientId: runtime.secrets.requiredString('OAUTH_CLIENT_ID'),
    clientSecret: runtime.secrets.requiredString('OAUTH_CLIENT_SECRET'),
    cacheTtl: const Duration(seconds: 30),
  ),
);

engine.get('/account', accountHandler, middlewares: [introspection]);
```

Keep client credentials in `RuntimeSecrets`, not in source-controlled
configuration objects.

## Auth provider and routes

For the built-in sign-in routes, bind typed `AuthOptions` before initializing
the `AuthServiceProvider`:

```dart
final engine = Engine(
  providers: [
    ...Engine.defaultProviders,
    RoutedSessionsProvider(
      SessionConfig.cookie(
        appKey: runtime.secrets.requiredString('SESSION_KEY'),
      ),
    ),
    AuthServiceProvider(),
  ],
);

engine.container.instance<AuthOptions<EngineContext>>(
  AuthOptions<EngineContext>(
    providers: [
      googleProvider(
        GoogleProviderOptions(
          clientId: runtime.secrets.requiredString('GOOGLE_CLIENT_ID'),
          clientSecret: runtime.secrets.requiredString('GOOGLE_CLIENT_SECRET'),
          redirectUri: 'https://example.com/auth/callback/google',
        ),
      ),
    ],
    sessionStrategy: AuthSessionStrategy.session,
    sessionMaxAge: const Duration(days: 30),
    sessionUpdateAge: const Duration(days: 1),
  ),
);

await engine.initialize();
```

The provider mounts `/auth/*` routes and resolves the configured auth manager.
The `AuthOptions` object is the application contract; there is no auth YAML
manifest or runtime string override.

## Organizations and tenant authorization

Organizations are an optional auth feature. Compose `OrganizationPlugin` to
add memberships, email-bound invitations, scoped roles, teams, automatic
Routed endpoints, a typed client, and tenant-aware Haigate helpers. See
[Organizations & Tenancy](/docs/routed/security/organizations) for setup,
persistence requirements, client usage, and the complete route surface.

## Administrative auth

Administration is also opt-in. Compose `AdminPlugin` for authoritative global
role checks, user and session management, bans, hard deletion, audit hooks, and
guarded server-session impersonation. See
[Administrative Auth](/docs/routed/security/admin) for setup, adapter
requirements, typed-client usage, and the route catalogue.

## Sessions, guards, and gates

Register `RoutedSessionsProvider` and add the session middleware before using
`SessionAuth`:

```dart
engine.addGlobalMiddleware(sessionMiddleware());

engine.get(
  '/admin',
  (ctx) => ctx.string('private'),
  middlewares: [
    guardMiddleware(['authenticated', 'admin']),
  ],
);

engine.post(
  '/reports/publish',
  (ctx) async {
    await Haigate.authorize('reports.publish', ctx: ctx);
    return ctx.string('published');
  },
  middlewares: [Haigate.middleware(['reports.publish'])],
);
```

Use `SessionAuth.login`, `SessionAuth.current`, and `SessionAuth.logout` for
the session lifecycle. Register broad role checks with `GuardRegistry` and
resource-specific abilities with Haigate. Remember-token storage should be
durable in production; the in-memory implementation is intended for tests.

## Events and callbacks

Auth lifecycle events are published through the engine’s `EventManager`:

```dart
final events = await engine.container.make<EventManager>();
events.listen<AuthSignInEvent>((event) {
  logger.info('auth sign in', {'user_id': event.user.id});
});
```

Callbacks on `AuthOptions` can gate sign-in, enrich session payloads, and
sanitize redirects. Keep redirect targets allow-listed and never return raw
provider errors to clients. Auth event model fields are safe projections:
provider credentials, account tokens, JWTs, credential fields, and nested
secret-like values are removed before delivery. Treat `event.context` as a
request-scoped private object and do not log its headers or cookies.

## Security checklist

- Keep JWT signing keys, OAuth credentials, and session keys in `RuntimeSecrets`.
- Pin accepted JWT algorithms and issuer/audience values.
- Configure trusted proxies before using forwarded client IPs in auth policy.
- Use secure, HttpOnly, appropriately `SameSite` session cookies.
- Return generic authentication errors and log detailed causes internally.
