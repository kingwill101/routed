# Security Features

Security settings are split between core engine configuration and the
`routed_security` provider. The provider owns CORS, trusted-proxy resolution,
request-size limits, and IP filtering. CSRF and response security headers are
explicit application middleware or core engine settings.

## Configure the security provider

```dart
import 'package:routed/routed.dart';

final engine = await Engine.create(
  providers: [
    ...Engine.defaultProviders,
    RoutedSecurityProvider(
      RoutedSecurityConfig(
        maxRequestSize: 10 * 1024 * 1024,
        trustedProxies: TrustedProxyConfig(
          enabled: true,
          proxies: ['10.0.0.0/8'],
          headers: ['X-Forwarded-For', 'X-Real-IP'],
          platformHeader: EngineConfig.platformCloudflare,
        ),
        ipFilter: IpFilterConfig(
          enabled: true,
          defaultAction: IpFilterAction.deny,
          allow: ['10.0.0.0/8'],
          respectTrustedProxies: true,
        ),
      ),
    ),
  ],
);
```

Only trust proxy networks controlled by your infrastructure. Otherwise a
client can forge forwarded headers and bypass IP decisions.

## CORS and security headers

Set CORS through the same typed provider:

```dart
final cors = RoutedSecurityConfig(
  cors: const CorsConfig(
    enabled: true,
    allowedOrigins: ['https://app.example.com'],
    allowedMethods: ['GET', 'POST'],
    allowedHeaders: ['Authorization', 'Content-Type'],
    allowCredentials: true,
    exposedHeaders: ['X-Request-ID'],
    maxAge: 600,
  ),
);
```

When CORS is enabled, the provider installs the CORS middleware and handles
valid `OPTIONS` preflight requests. Do not use wildcard origins with
credentials.

Security headers remain explicit middleware so applications can choose a
policy appropriate to their deployment:

```dart
engine.use((ctx, next) async {
  ctx.setHeader('X-Content-Type-Options', 'nosniff');
  ctx.setHeader('X-Frame-Options', 'DENY');
  ctx.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
  ctx.setHeader('Content-Security-Policy', "default-src 'self'");
  return next();
});
```

Avoid `X-XSS-Protection`; it is deprecated in modern browsers. Use a strong
CSP instead.

## CSRF and HTTPS

CSRF protection requires sessions. Register `RoutedSessionsProvider` with a
`SessionConfig` and add the CSRF middleware at the application boundary. Keep
session cookies `HttpOnly`, `Secure` in production, and use an appropriate
`SameSite` policy.

Use `serveSecure` for native TLS or terminate TLS at a trusted edge and pass
the edge’s proxy network to `TrustedProxyConfig`.
